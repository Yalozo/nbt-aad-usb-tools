# NBT-AAD PC для Windows

**Версия 0.1.5** содержит установщик 0.4.0, адаптированный к реальному набору утилит NBT Evo: без обязательных `id`, `printf`, `awk`, `cmp`, `od`, `rmdir` и `sync`. Если у вас EXE предыдущей версии, скачайте новую сборку целиком.

Бесплатное приложение для установки, обновления и удаления [NBT-AAD](https://github.com/Sq00ky/Supra-iDrive6-Android-Auto) на BMW и MINI с NBT Evo ID5/ID6. Флешка и PuTTY не требуются: файлы передаются по SSH через проводной ENET.

## Пользователю

1. Скачайте архив **NBT-AAD-PC-Windows-x64** из успешно завершённой [сборки Windows](https://github.com/Yalozo/nbt-aad-usb-tools/actions/workflows/windows.yml) и распакуйте его.
2. Запустите `NBT-AAD-PC.exe`. Python устанавливать не нужно. Приложение рассчитано на Windows 10/11 x64 и не требует запуска от администратора.
3. Подключите ENET, включите ГУ и откройте root SSH, например через [Bavarian SSH Client](https://ssh.bavarian-aa.uk/). Открытие SSH остаётся отдельным действием: приложение не реализует механизм разблокировки стороннего клиента.
4. Оставьте обычные параметры подключения `169.254.199.99:22`, логин `root` и типовой пароль `ts&SK412` либо укажите свои. Поддерживается и прямое подключение к `169.254.199.119:22`. При первом подключении подтвердите ключ своего ГУ; изменившийся сохранённый ключ программа отвергнет.
5. Нажмите **Установить / обновить**. Программа скачает подходящий релиз, проверит SHA-256 файлов, загрузит программу и плагин во временный каталог ГУ, выполнит проверочный запуск и установку с резервными копиями. Настройки существующей установки сохраняются.
6. После подтверждённого успеха программа проверит установленные пути и запросит перезагрузку командой `OnOffDSICommander appreset`. Дождитесь штатного меню, откройте **Медиа/Радио → Android Auto**. При первом запуске может потребоваться повторное сопряжение телефона с обеих сторон.

Перед нажатием **Удалить** выберите режим:

- **Сохранить настройки и резервные копии** (по умолчанию): удаляет бинарник и плагин, оставляет файлы конфигурации в `/opt/aa` (включая `nbt-aad.env`) и все настройки `/var/opt/aa`. При повторной установке они используются снова. Предыдущие программа и плагин остаются в резервной копии.
- **Полная очистка**: после остановки демона и удаления программы стирает `/opt/aa`, плагин, `/var/opt/aa`, обе папки резервных копий, временные загрузки `/var/opt/nbt-aad-pc-<32 hex>` и известные RAM-файлы состояния/журналов NBT-AAD. Нуждается в отдельном подтверждении; восстановление из удалённых копий невозможно. При ошибке стирания успех не выводится; очистку можно повторить.

Интернет и скачанный релиз для удаления не требуются. Флажок перезагрузки действует на оба режима. Загруженный в HMI плагин освобождается только при перезагрузке, до неё он может заново создать RAM-состояние. Общие кэши HMI и системные журналы, SSH, CarPlay, сопряжения Bluetooth и нестандартные пути, заданные вручную, не очищаются. Это очистка файлов проекта в известных путях, а не гарантированное уничтожение всех исторических следов в прошивке. Файлы на флешке и в библиотеке ПК сохраняются.

**Перезагрузить ГУ** — отдельная команда перезапуска через уже открытый SSH. Не требует скачанного комплекта или установленного Android Auto, не загружает файлы и не запускает установщик. Выполняется проверка QNX, узла и root-доступа, затем `OnOffDSICommander appreset`. Флажок перезагрузки после установки на эту кнопку не влияет. Закрытие SSH после подтверждения отправки команды ожидаемо; при временной разблокировке SSH может потребоваться открыть его заново.

**Состояние** — проверяет файлы и процесс NBT-AAD без записи на ГУ и без интернета. Программа читает встроенные номера сборок из установленного бинарника и плагина (например, `v1.8.66-kombi-bt` и `rhmiapp-24b-credits`). Это работает и после ручной установки. Дополнительно сравнивает SHA-256 всех шести файлов с библиотекой скачанных комплектов: при полном совпадении показывает название и тег релиза. Если номера не найдены или совпадения нет, сообщает об этом; версия не угадывается по последнему релизу, старому журналу или сохранённой записи установки. Бинарник для проверки версии не запускается. Наличие процесса не является тестом подключения Android Auto.

Приложение не активирует CarPlay, не меняет FSC/кодирование и не перепрошивает ГУ. Нужны совместимое NBT Evo, активированный CarPlay с Wi-Fi-антенной, проводной Ethernet/OABR и уже открытый root SSH. NBT Evo ID4 после перепрошивки в ID5/ID6 требует отдельной проверки на конкретном блоке; обычный NBT не поддерживается.

## Выбор релиза и установка без интернета

По умолчанию выбирается наиболее новый по дате публикации релиз с полным комплектом файлов. Исключаются и GitHub pre-release, и названия/теги alpha, beta, preview, rc — даже если автор не отметил их как pre-release. Для экспериментов есть флажок **Показывать бета-релизы** и список версий. Старый релиз можно выбрать вручную, в том числе для установки более ранней версии; совместимость его настроек зависит от самого NBT-AAD.

**Скачать заранее** загружает выбранный интернет-релиз на ноутбук без подключения к автомобилю. Все успешно скачанные комплекты остаются в библиотеке: новая версия не заменяет старую. Одинаковый комплект повторно не дублируется. Папки, скачанные предыдущими версиями приложения в тот же профиль Windows, обнаруживаются автоматически.

В гараже:

1. Включите **Использовать скачанный комплект (без интернета)**.
2. В списке **Сохранённые комплекты** выберите нужную версию. В названии показаны релиз, тег и дата публикации; если автор переиспользовал название/тег для разных файлов, добавляется короткий идентификатор сборки. Бета-версии помечены отдельно.
3. Нажмите **Установить / обновить**. Загружается строго выбранная локальная копия. Она повторно проверяется по контрольным суммам; при повреждении/исчезновении установка останавливается без подмены версии и без перехода к скачиванию.

Офлайн-режим и выбранная локальная версия сохраняются между запусками. **Обновить список** перечитывает локальные файлы без обращения к интернету. Удаление старых комплектов автоматически не выполняется. Повреждённые и незавершённые загрузки исключаются из списка с записью причины в журнал; сами файлы при этом не удаляются.

В офлайн-режиме интернет-список и кнопки скачивания отключены. Чтобы загрузить ещё один релиз, снимите флажок офлайн-режима, выберите интернет-релиз и нажмите **Скачать заранее**. Для открытия закрытого SSH через Bavarian клиенту по-прежнему может потребоваться интернет.

Бинарник и плагин всегда берутся из одного релиза. Перемещаемые автором теги не считаются постоянным идентификатором: кэш привязан к контрольным суммам обоих файлов. Если состав плагина изменится, контрольная сумма отсутствует или проверка не пройдёт, автоматическая установка остановится.

## Журналы и ошибки

На ГУ без `sync` программа не выполняет явный сброс файловых кэшей этой утилитой; это отражается в журнале. Команда перезагрузки остаётся `OnOffDSICommander appreset`.

Журналы: `%LOCALAPPDATA%\NBT-AAD-PC\logs`. Комплекты: `%LOCALAPPDATA%\NBT-AAD-PC\packages`. Адрес и порт сохраняются в `settings.json`, пароль не записывается. Ключи ГУ хранятся в `known_hosts`.

На ГУ используются уникальные временные каталоги `/var/opt/nbt-aad-pc-<32 hex>`. В QNX `/dev/shmem` не поддерживает подкаталоги, поэтому для загрузки он не применяется. Требуется доступный для записи `/var/opt`. Переданные файлы считываются обратно и проверяются на ноутбуке. После успешной операции каталог очищается. Для проверки заголовков скрипт также создаёт и удаляет несколько временных байт внутри этого каталога; рабочие каталоги приложения и настроек в проверочном режиме не меняются. При неопределённом результате временная загрузка сохраняется для диагностики: автоматическое исчезновение после перезагрузки не гарантируется. Точный путь есть в журнале; резервные копии не удаляются. На время передачи и установки не отключайте питание или ENET.

Успех определяется по коду завершения, сообщению установщика и дополнительной проверке рабочих путей. Обрыв SSH до этого момента считается ошибкой, а не успешной установкой. Обрыв при последующей перезагрузке выводится отдельно; программа не утверждает, что загрузка ГУ уже завершилась. При ошибке/откате автоматическая перезагрузка не запрашивается.

Резервные копии: `/opt/nbt-aad-usb-tools-backups` и `/var/opt/nbt-aad-usb-tools-backups`. См. [восстановление](../docs/RECOVERY.md). Автоматического удаления резервных копий нет; они стираются только при явно выбранной полной очистке. Ошибка полной очистки может означать частичное стирание — оставшиеся копии и временные файлы проверяют по журналу, их сохранность не гарантируется.

## Разработчику

Python 3.12 x64 на Windows, Tkinter, Paramiko. Из корня `windows`:

```powershell
python -m pip install -r requirements.txt
python main.py
```

Сборка самостоятельного EXE и проверки:

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

Результат: `windows/dist/NBT-AAD-PC.exe`. Сборка запускается на Windows, в том числе через GitHub Actions. `main.py --self-test` проверяет наличие GUI, SSH-библиотеки, доверенных TLS-сертификатов и вложенного установщика в собранном EXE. Тесты проверяют загрузку/кэш, архивы, ошибки установки, перенаправление узлов, перезапуск и реальные SSH-сессии с RSA/HMAC-SHA1 на локальном тестовом сервере. Тест GUI выполняется на Windows. Эти проверки не заменяют испытание на реальном ГУ.
