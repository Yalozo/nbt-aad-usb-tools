# NBT-AAD Installer для Android

Установка, обновление, проверка состояния и удаление NBT-AAD на BMW и MINI с NBT Evo ID5/ID6. Приложение использует тот же `nbt-aad.sh`, что и установщики для Windows и macOS. Подключите ENET через USB–Ethernet или подключите телефон и ГУ к одной локальной сети с Wi-Fi. Для SSH нужен root-доступ к своему ГУ.

**Кодирование ГУ перед установкой.** В разделе `3000 HMI` должны быть включены `A4A = aktiv` и `REMOTE_HMI = aktiv`. Остальные параметры для вашей прошивки проверьте по требованиям NBT-AAD. Без нужного кодирования HMI может пропустить плагин, поэтому пункт Android Auto не появится даже после успешного копирования файлов. Кодирование выполняется отдельно через E-Sys, BimmerCode или другой совместимый инструмент. [Требования NBT-AAD к кодированию](https://github.com/Sq00ky/Supra-iDrive6-Android-Auto/blob/main/coding-requirements.md)

1. Подключите USB–Ethernet-адаптер к телефону и кабелю ENET или подключите телефон и ГУ к одной локальной сети. Включите зажигание и нажмите **«Состояние»**.
2. Нажмите **«Проверить релизы»**, чтобы выбрать сборку из официального проекта Sq00ky. Режим **«Авто»** выбирает последний подходящий стабильный релиз. Для просмотра бета-релизов включите соответствующий флажок.
3. Нажмите **«Установить / обновить»**. Если ГУ ещё не знакомо приложению, сверьте отпечаток SSH-ключа перед подтверждением. При закрытом SSH приложение предложит открыть доступ через fix-bmw.ru. Этот сервис получает диагностические данные, которые могут содержать VIN и сведения о ГУ.
4. Оставьте питание и кабель подключёнными до окончания операции. Если отмечена перезагрузка, приложение отправит по диагностике `ECUReset 11 01` после проверки изменённых файлов. Дождитесь штатного меню ГУ, затем откройте Android Auto в меню «Медиа/Радио».

**«Скачать заранее»** сохраняет проверенный комплект во внутреннем хранилище Android. Когда SSH уже открыт, скачанный комплект можно установить без интернета. Для GitHub и сервиса открытия SSH используется отдельное от ENET подключение через Wi-Fi или мобильную сеть. В **«Параметрах SSH и диагностики»** можно задать IP и порт SSH, а также IP диагностики. Введённый пароль остаётся только в текущем сеансе приложения.

При пустых полях IP SSH и IP диагностики приложение последовательно проверяет активные интерфейсы Ethernet и Wi-Fi с IPv4. Найденные адреса появятся в журнале при проверке соединения и обращении к ГУ. Начиная с 1.0.6, найденный через Wi-Fi маршрут используется также для открытия закрытого SSH и последующих действий. Приложение проверяет стандартные адреса `169.254.199.99` и `169.254.199.119` через эту сеть, поскольку адрес диагностики и адрес SSH могут находиться в разных подсетях. Если SSH уже открыт на другом локальном адресе, приложение ищет сервер QNX в пределах одного `/24`. В параметрах можно задать IP SSH и диагностики вручную для подключения через Wi-Fi.

При нескольких ответах SSH QNX приложение предлагает выбрать IP. С версии 1.0.8 выбор хранится в памяти до закрытия приложения. Если адрес перестал отвечать, приложение повторяет поиск. При первом запуске обновления сохранённый ранее IP переносится в текущий сеанс. Для постоянного адреса сохраните IP вручную в параметрах SSH. Если сервис открытия прислал неизвестную команду, приложение проверяет доступность SSH и выполняет обычную проверку ключа, типа ГУ и root-доступа. Код неизвестной команды появляется в журнале.

**«Состояние»** показывает версию прошивки, файлы, процесс, встроенные версии NBT-AAD и плагина. Если файлы совпадают со скачанным комплектом по SHA-256, журнал покажет соответствующий релиз. **«Удалить»** сохраняет настройки и резервные копии. **«Очистить ГУ»** убирает правила NBT-AAD из сетевого фильтра и удаляет его файлы, настройки и резервные копии после отдельного подтверждения. **«Перезагрузить ГУ»** доступна отдельно. Последний журнал можно сохранить в файл или отправить через меню Android.

С версии 1.0.9 кнопка **«Перезагрузить ГУ»** работает по диагностике через TCP 6801. Приложение находит диагностический шлюз BMW и отправляет HSFZ-кадр `00 00 00 04 00 01 f4 63 11 01` для ГУ `0x63`. Отдельная перезагрузка доступна при закрытом SSH. Ответ `63 f4 51 01` подтверждает принятие запроса. При разрыве соединения или таймауте журнал сообщает, что результат требует проверки. Каждый запрос отправляется однократно. На стенде получен положительный ответ и подтверждена последующая доступность диагностики при закрытом SSH.

Перед изменением файлов приложение проверяет комплект, передаёт его в частный временный каталог на `hu-omap` и сверяет SHA-256 каждого переданного файла. Общий скрипт проверяет условия операции, создаёт резервные копии и откатывает изменения при сбое. Перезагрузка запрашивается после подтверждения результата. [Восстановление на ГУ](../docs/RECOVERY.md)

При установке через SSH скрипт выполняет `pf_aa --install` и `pf_aa --check` до перезапуска. Для новых релизов он может вызвать эквивалентные команды внутри `nbt-aad`. Если проверка не проходит, скрипт восстанавливает предыдущую конфигурацию и файлы установки. [Работа с PF](../docs/PF-AA.md)

С версии 1.0.10 «Состояние» распознаёт PF, встроенный в `nbt-aad`, и выполняет проверку `--pf-check`. Для отдельной утилиты используется `pf_aa --check`. Журнал показывает встроенную версию и результат проверки правил.

**«Редактировать nbt-aad.env»** открывает `/opt/aa/nbt-aad.env` на ГУ. Кнопка **«Отладочные параметры»** позволяет настроить `NBT_BT_TRACE`, `NBT_MOST_LOG`, `NBT_RAM_LOG` и `NBT_DIAG`. Чтобы выключить `NBT_DIAG`, удалите эту строку. Другие параметры `NBT_` можно ввести вручную в формате `КЛЮЧ=значение`. Плагин iDrive читает до 15 настроек. Пишите комментарии на отдельных строках с `#` в начале. При сохранении приложение сверяет исходный файл и, если он существовал, сохраняет предыдущую версию в `/opt/aa/nbt-aad.env.bak`. Для применения параметров демона перезапустите NBT-AAD из меню iDrive.

## Ethernet на Samsung Galaxy

Если Android не показывает Ethernet-сеть с IPv4, приложение ищет адрес на самом проводном интерфейсе. Если Android показывает сеть, но через неё не удаётся отправить ни одного пакета поиска, приложение повторяет поиск с привязкой к локальному IPv4 интерфейса. При подключённом адаптере режим модема включается в **«Подключения» → «Мобильная точка доступа и модем» → «Ethernet-модем»**. После возврата приложение повторит проверку. Поиск шлюза использует UDP и проверку порта TCP 6801 в локальной подсети. В широких подсетях проверка TCP ограничена одним `/24`.

Диагностический шлюз может отвечать с адреса `10.x.x.x`, а SSH ГУ оставаться на адресах `169.254.x.x`. Приложение проверяет также адрес шлюза и ищет SSH ГУ в локальной подсети. Если известен отдельный адрес SSH ГУ, укажите его в параметрах приложения. Успех открытия порта отображается отдельно от доступности SSH с телефона.

Если диагностика или SSH через модем недоступны, выключите Ethernet-модем. В **«Подключения» → «Другие настройки соединения» → «Ethernet»** задайте IP `169.254.107.10` с маской `255.255.0.0` (префикс `16`). Если система требует шлюз, укажите `169.254.1.1`. Кнопка в подсказке копирует IP и открывает системные настройки. Это сочетание проверено на Galaxy S24 для связи с ГУ и чтения его версии по SSH.

## Сборка

Проект требует Android SDK Platform 35 и JDK 17. APK рассчитан на Android 6.0 и новее. Из каталога проекта запустите `./build-local.sh testDebugUnitTest --offline` при наличии локального SDK и кэша зависимостей. В Android Studio можно собрать debug APK через меню **Build**. Результат находится в `app/build/outputs/apk/debug/app-debug.apk`. Сборка автоматически включает `../nbt-aad.sh`. Бинарники NBT-AAD загружаются отдельно из [официальных релизов](https://github.com/Sq00ky/Supra-iDrive6-Android-Auto/releases).
