# pf_aa: назначение и поддержка в установщике

[English](PF-AA.en.md)

С версии приложения **0.1.8** и USB-скрипта **0.4.1** необязательный `pf_aa` включается в комплект, если он приложен к выбранному релизу NBT-AAD. Старые комплекты без него поддерживаются.

## Для чего он нужен

По [исходнику утилиты](https://github.com/Sq00ky/Supra-iDrive6-Android-Auto/blob/629fb372b648de8d50b842eae40f5b7f75d0bbf2/milestone-7/tools/pf_aa.cpp) и [описанию правил](https://github.com/Sq00ky/Supra-iDrive6-Android-Auto/blob/629fb372b648de8d50b842eae40f5b7f75d0bbf2/milestone-7/tools/pf_aa.hpp), это инструмент настройки packet filter, а не второй демон Android Auto.

Обычный путь запуска демона выключает packet filter через `pfctl -d`, если не задан `NBT_KEEP_PF=1`. Утилита предлагает другой режим: разрешить соединения Android Auto на TCP 5277 через Wi-Fi-интерфейсы `uap0` и `wfd0`, сохранив работу фильтра. Это не инструмент открытия SSH.

При `--install` утилита:

- сохраняет вариант конфигурации без правил AA в `/opt/aa/pf.bak`;
- добавляет необходимые правила в `/fs/sda0/etc/pf.conf` (с запасным путём `/etc/pf.conf`);
- добавляет `NBT_KEEP_PF=1` в `/opt/aa/nbt-aad.env`;
- проверяет синтаксис через `pfctl -n` и сверяет запись с прочитанными файлами.

Утилита не загружает новые правила в работающий фильтр автоматически: авторы предусматривают последующую перезагрузку ГУ либо отдельную перезагрузку правил. Только первые 15 настроек env передаются плагином; сама утилита предупреждает, если новый параметр оказался дальше.

## Что делает наш установщик

Он скачивает `pf_aa` из того же релиза, проверяет размер/SHA-256/ARM ELF32, включает файл в офлайн-копию и устанавливает в `/opt/aa/pf_aa` с правами 755. При обновлении прежняя папка `/opt/aa`, включая утилиту и её конфигурацию, сохраняется в резервной копии.

**Установщик не запускает `pf_aa --install` автоматически.** Само наличие файла не включает этот режим и не меняет `pf.conf` или `NBT_KEEP_PF`. В исходном проекте это отдельная утилита; обязательным условием обычной установки она не объявлена. Текущий способ запуска AA сохраняется.

Кнопка «Состояние» читает встроенный номер версии утилиты без её запуска и сравнивает установленный комплект с локальной библиотекой: шесть файлов для прежних релизов либо семь, если в комплект входит `pf_aa`.

Если файл появился в уже скачанном релизе позже, скачайте комплект заново. Новая копия получит другой идентификатор, поскольку в него входит также SHA-256 `pf_aa`. Старая локальная копия не изменяется и остаётся доступной.

## Отдельное использование утилиты

Следующие команды — дополнительная настройка для тех, кто решил включить этот режим. Они выполняются в root SSH **на hu-omap**, после установки файла:

```sh
/opt/aa/pf_aa --check
/opt/aa/pf_aa --install
OnOffDSICommander appreset
```

`--check` сообщает о правилах, параметре env и состоянии фильтра; код 7 означает неполную настройку, а не повреждение установщика. Перезагрузка должна выполняться только после успешного завершения `--install`. Для обычного использования GUI-установщика этот дополнительный шаг не обязателен.

Перед отдельным восстановлением:

```sh
/opt/aa/pf_aa --uninstall
```

**Восстановление возвращает файл из `pf.bak` целиком.** Если после создания копии вы меняли другие правила, сначала сравните файлы и учтите эти изменения. Утилита также убирает `NBT_KEEP_PF` из env. После восстановления нужна перезагрузка ГУ для применения конфигурации.

Если обычное удаление уже убрало `pf_aa`, его прежняя копия находится в `aa` соответствующего архива установщика; можно также заново установить комплект. Не удаляйте `pf.bak` до восстановления конфигурации.

## Удаление и полная очистка

Обычное удаление убирает бинарник утилиты вместе с демоном. В режиме сохранения настроек `pf.bak` и env остаются на месте; в архивном CLI-режиме сохраняются в архиве прежней папки `aa`.

Полная очистка сначала ищет `pf.bak` в действующей папке и прежних архивах. Если копия найдена, а в системном `pf.conf` остаются правила `pass` для 5277 или конфигурацию нельзя прочитать, очистка останавливается до изменений. Так она не стирает единственную возможность восстановления отдельно применённых правил. После восстановления правил очистку можно повторить. Установщик не переписывает системный фильтр из старой копии автоматически.

## Проверенный файл

В релизах `cc-pf`, `volsliderfixforreal`, `winmgr` и `Installer` при исследовании был приложен один и тот же ARM ELF32 `pf_aa`:

- версия во встроенной строке: **1.1**;
- размер: **39844 байта**;
- SHA-256: `5ae04c87476a041cad945e2afe6da7067ac3defdd9beea96407d8b3a3df339bb`.

Номер прочитан из файла, бинарник на компьютере не запускался. В версии 1.1 авторы учли возврат ENOSYS при fsync файла в QNX /dev/shmem. Новые версии проверяются по своим контрольным суммам из соответствующего релиза, а не по этому фиксированному значению.
