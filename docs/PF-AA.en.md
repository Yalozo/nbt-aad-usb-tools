# Optional pf_aa support

[Русский](PF-AA.md)

Desktop installer 0.1.8 and USB installer 0.4.1 added support for optional `pf_aa` files supplied by an NBT-AAD release. Older packages without this file still work.

## Purpose

`pf_aa` configures the QNX packet filter. With the default daemon startup, `pfctl -d` disables filtering unless `NBT_KEEP_PF=1` is present. The optional mode keeps the filter active while allowing Android Auto on TCP port 5277 via the `uap0` and `wfd0` Wi-Fi interfaces. [Utility source](https://github.com/Sq00ky/Supra-iDrive6-Android-Auto/blob/629fb372b648de8d50b842eae40f5b7f75d0bbf2/milestone-7/tools/pf_aa.cpp) · [Rules](https://github.com/Sq00ky/Supra-iDrive6-Android-Auto/blob/629fb372b648de8d50b842eae40f5b7f75d0bbf2/milestone-7/tools/pf_aa.hpp)

With `--install`, the utility saves a copy without Android Auto rules in `/opt/aa/pf.bak`, adds its rules to `/fs/sda0/etc/pf.conf` or `/etc/pf.conf`, sets `NBT_KEEP_PF=1` in `/opt/aa/nbt-aad.env`, checks syntax with `pfctl -n`, and reads back the files. The plugin passes only the first 15 environment settings. The utility reports if the new entry is beyond that limit. The rules take effect after reloading them or restarting the head unit.

## What the installer does

Status in Android 1.0.10 and desktop app 0.1.19 recognizes both standalone and embedded PF utilities. After identifying a version in a validated ARM ELF32 file, it runs `--check` or `--pf-check`. The report includes configuration verification and the loaded rule state when the utility supports that check.

It downloads `pf_aa` from the selected release, verifies the size, SHA-256, and ARM ELF32 header, caches it for offline use, and installs it as `/opt/aa/pf_aa` with mode 755. The previous executable and settings in `/opt/aa` are backed up on update. **Status** reads the embedded utility version and compares all six or seven files against cached packages. If `pf_aa` was added upstream after downloading the release, download it again.

For SSH installs, script **0.4.3** saves an exact copy of the previous `pf.conf` as `pf.conf.before`, runs `--install` and `--check`, and confirms success before the head unit restarts. Windows, macOS, and Android use embedded `--pf-install` and `--pf-check` when the selected daemon provides them and the standalone utility is absent. Releases without either utility skip this step. Installation from a flash drive copies the utility for manual use.

On failure, the script restores the previous `pf.conf`, application files, and settings. Exit code `9` confirms that the on-disk configuration passed validation and will take effect after restart.

## Applying and restoring rules

For manual setup, run the first two commands over SSH on `hu-omap`. Run the third command after installation and verification succeed.

```sh
/opt/aa/pf_aa --install
/opt/aa/pf_aa --check
OnOffDSICommander appreset
```

`--check` reports the rules, environment setting, and filter state. Exit code `7` indicates incomplete configuration. The embedded commands are `/opt/aa/nbt-aad --pf-install` and `/opt/aa/nbt-aad --pf-check`.

To restore the previous settings:

```sh
/opt/aa/pf_aa --uninstall
```

The embedded equivalent is `/opt/aa/nbt-aad --pf-uninstall`. The utility restores the entire `pf.bak` file and removes `NBT_KEEP_PF` from the environment file. Compare the configurations first if other rules changed after the backup. Restart to apply the restored configuration. If ordinary removal already removed the binary, find it in the installer's `aa` backup. Keep `pf.bak` until the configuration is restored.

## Removal and full cleanup

Ordinary removal deletes the executable along with the daemon. The keep-settings mode leaves `pf.bak` and the environment file in place. Archived CLI removal keeps them in the old `aa` folder.

Starting with 0.4.4, full cleanup removes the standard rules generated by `pf_aa` from the current `pf.conf`, even if NBT-AAD has already been removed. Other lines are kept. The script checks the syntax with `pfctl -n` before and after writing. On failure it preserves the original configuration and NBT-AAD files. When a backup exists, unrecognized Android Auto rules require manual restoration before cleanup. Restart the head unit to apply the on-disk changes.

The examined `cc-pf`, `volsliderfixforreal`, `winmgr`, and `Installer` releases contained the same 39,844-byte ARM ELF32 utility, version 1.1. Its SHA-256 is `5ae04c87476a041cad945e2afe6da7067ac3defdd9beea96407d8b3a3df339bb`. Version 1.1 handles ENOSYS from fsync on QNX `/dev/shmem`. The installer validates newer files against the digest in their own release.
