# NBT-AAD USB Tools

[English](README.en.md)

Установка, обновление и удаление [NBT-AAD](https://github.com/Sq00ky/Supra-iDrive6-Android-Auto) через SSH с автоматическим поиском флешки. Скрипт рассчитан на QNX в NBT Evo ID5/ID6. При запуске на `hu-jacinto` он автоматически продолжает работу на `hu-omap` через `on -f`. При прямом входе на `hu-omap` переход пропускается.

**Версия установщика: v0.4.2.** Проверены синтаксис POSIX sh и 65 интеграционных сценариев в изолированных каталогах компьютера.

Приложение проверяет SSH перед обращением к ГУ, показывает онлайн-релизы и скачанные комплекты в одном списке и использует SHA-256 для проверки файлов. Есть определение установленной версии, обычное удаление, полная очистка, перезагрузка и отправка журнала через почтовый клиент. Скрипт устанавливает программу и пункт меню Android Auto. Для начала работы уже нужны root SSH и Ethernet-доступ к голове через ENET/OABR. Для ручного запуска USB-скрипта войдите по root SSH. ## Исправление для штатного набора команд NBT Evo

Версия 0.3.3 адаптирована к подтверждённому набору команд реального `hu-omap`: для неё не нужны `id`, `printf`, `awk`, `cmp`, `od` и `rmdir`. Root проверяется через штатный `pidin`, его вывод разбирается средствами оболочки. Заголовки ELF/ZIP проверяются через `dd`, `diff`, `wc` и встроенный `echo`; двоичные данные не проходят через переменные оболочки. После копирования все файлы комплекта сравниваются через `diff` без игнорирования различий.

Утилита `sync` на проверенном ГУ также отсутствует. Скрипт вызывает её только при наличии; если её нет, это явно указывается в журнале. Задержка или чтение файла не выдаются за эквивалент принудительного сброса данных на диск. Перезапуск выполняется документированной командой `OnOffDSICommander appreset`.

Windows-приложение исправлено в версии **0.1.3**. Старый EXE содержит прежний установщик, его тоже нужно заменить. Набор утилит тестируется с изолированным PATH на основе предоставленного списка `/bin`; проверка на реальном автомобиле всё равно необходима.

В QNX `/dev/shmem` не поддерживает подкаталоги и представляет объекты особого типа. Поэтому в версии 0.3.3 проверки выполняются на обычной файловой системе источника, а блокировка и загрузка Windows — под `/var/opt`. См. [документацию QNX](https://qnx.com/developers/docs/6.4.1/neutrino/user_guide/fsystems.html).

## Подготовка флешки

1. Использовать флешку FAT32 или exFAT. Если требуется форматирование, предварительно сохранить её содержимое.
2. Скачать **оба файла из одного официального релиза**: `nbt-aad` и архив плагина (`release.zip`, `Releases.zip` и т. п.). [Официальные релизы](https://github.com/Sq00ky/Supra-iDrive6-Android-Auto/releases).
3. Положить `nbt-aad` в корень флешки. Распаковать архив плагина.
4. Положить `nbt-aad.sh` из этого проекта в корень флешки.

Ожидаемая структура:

```text
USB/
├── nbt-aad.sh
├── nbt-aad
├── pf_aa             # если присутствует в выбранном релизе
└── release/
    ├── libNbtAad.so
    ├── NbtAad.manifest
    ├── NbtAad.xml
    ├── NbtAad_ALL_Texts.zip
    └── NbtAad_ALL_Images.zip
```

Поддерживаются имена папки `release`, `releases` с любым регистром букв, включая `Releases`, а также размещение всех пяти файлов плагина в корне. Два внутренних ZIP с текстами и изображениями распаковывать не нужно.

На флешке должен быть один комплект плагина. При нескольких подходящих флешках или папках скрипт останавливается. Дополнительные файлы из исходного архива автоматически в голову не копируются: состав установки ограничен шестью перечисленными файлами и необязательным `pf_aa`, если он есть в релизе. Положите `pf_aa` рядом с `nbt-aad` в корне флешки; файл проходит ту же проверку ARM ELF32 и копируется в `/opt/aa/pf_aa` с правами запуска. Настройка фильтра отдельно описана в [PF-AA.md](docs/PF-AA.md); автоматически утилита не запускается.

## Подключение и первая проверка

Вставить флешку в USB машины. Открыть SSH и войти под `root`. Ручная команда `on -f` больше не требуется: скрипт проверяет текущий узел и при необходимости запускает себя на `hu-omap`.

Здесь и далее команды выполняются **в SSH на голове**. На компьютере запускать `nbt-aad.sh` не нужно. В командах используется путь `/net/hu-omap/mnt/…`, чтобы найти файл скрипта и тогда, когда флешка ещё не видна в локальном `/mnt` узла SSH.

Проверить комплект без изменений:

```sh
/bin/sh /net/hu-omap/mnt/umass*/nbt-aad.sh install --dry-run
```

После автоматического перехода скрипт найдёт флешку, проверит наличие файлов, заголовки ARM ELF32 и ZIP, тип головного узла и необходимые команды. Режим `--dry-run` не перемонтирует файловую систему, не останавливает процессы и не пишет в постоянные каталоги установки. Для сравнения бинарных заголовков он создаёт временный закрытый каталог `nbt-aad-header-check-<PID>` на выбранной флешке (либо внутри каталога SSH-загрузки) и удаляет его при завершении, в том числе при ошибке. Источник комплекта должен быть доступен для записи. Файлы приложения и его настроек в проверочном режиме не меняются. Успешная проверка заголовков не доказывает совместимость релиза с конкретной прошивкой.

Шаблон `/net/hu-omap/mnt/umass*/nbt-aad.sh` также автоматически находит сам скрипт. Если одинаковый скрипт находится на двух флешках, команда остановится до изменений; оставить одну или указать точный путь.

Если SSH уже открыт непосредственно на `hu-omap`, а путь к этому же узлу через `/net/hu-omap` недоступен, использовать локальный вариант: `/bin/sh /mnt/umass*/nbt-aad.sh install --dry-run`. Скрипт распознает `hu-omap` и останется на нём.

## Установка или обновление

Закрыть меню Android Auto на время операции. Для обновления удобно заранее выполнить **Force Stop** в iDrive. Если демон всё же работает, скрипт отправит только найденным процессам `nbt-aad` сигнал SIGTERM и подождёт до 20 секунд. Если они не завершатся, замена файлов не начнётся; принудительного SIGKILL нет.

```sh
/bin/sh /net/hu-omap/mnt/umass*/nbt-aad.sh install
```

Порядок работы:

1. Проверка окружения, автоматический переход на `hu-omap` при необходимости и проверка источника.
2. Перемонтирование `/fs/sda0` в режим записи, как в официальной инструкции.
3. Подготовка копии новой программы и плагина с проверкой полного содержимого через `diff`.
4. Корректная остановка работающего демона.
5. Перемещение прежних каталогов в резервную папку и установка подготовленных каталогов через переименование.
6. Синхронизация файловой системы и сохранение журнала операции.

Настройки в `/opt/aa`, включая `nbt-aad.env`, сохраняются при обновлении. Содержимое `/var/opt/aa`, в том числе автозапуск и настройки сопряжения NBT-AAD, при установке/обновлении сохраняется. Отдельные настройки экрана, тайм-аутов, звука и автозапуска установщик не задаёт.

Старая библиотека плагина остаётся в резервной папке вне дерева `Plugins`: уже загруженный файл не перезаписывается, а второй экземпляр плагина не появляется в меню.

После успеха **перезагрузить ГУ**; параметр `--restart-hmi` выполняет это автоматически. Затем открыть **Media/Radio → Android Auto**, включить **Save logs to USB** и запустить подключение. Телефон должен быть сопряжён для звонков и Bluetooth-аудио. При первом подключении может понадобиться удалить сопряжение с обеих сторон и выполнить его заново.

## Удаление

Для удаления достаточно флешки с `nbt-aad.sh`; файлы релиза не нужны.

```sh
/bin/sh /net/hu-omap/mnt/umass*/nbt-aad.sh uninstall --dry-run
/bin/sh /net/hu-omap/mnt/umass*/nbt-aad.sh uninstall
```

После остановки демона скрипт **переносит в резервные папки**:

- `/opt/aa` — программу, локальные настройки и старые файлы, находившиеся в этом каталоге;
- `/opt/hmi/ID5/data/ro/Plugins/NbtAad` — плагин меню;
- `/var/opt/aa` — постоянные настройки NBT-AAD, включая флаг автозапуска.

Затем нужна перезагрузка ГУ; с `--restart-hmi` она запрашивается автоматически. Повторное удаление при отсутствии всех трёх каталогов ничего не меняет. Резервные копии и журналы на флешке сохраняются; повторная установка после удаления будет использовать настройки по умолчанию NBT-AAD, если старые настройки не восстановить вручную.

Удаление охватывает именно установку в этих стандартных путях. Внесённые вручную изменения в другие каталоги, загрузочные конфигурации или сторонние пакеты нужно учитывать отдельно.

### Сохранение настроек и полная очистка (0.4.0)

```sh
# Оставить nbt-aad.env и прочую конфигурацию /opt/aa, настройки /var/opt/aa и копии:
/bin/sh /net/hu-omap/mnt/umass*/nbt-aad.sh uninstall --keep-config --restart-hmi

# Сначала посмотреть точный список удаления без изменений:
/bin/sh /net/hu-omap/mnt/umass*/nbt-aad.sh uninstall --purge --dry-run
# Стереть программу, плагин, настройки, обе папки копий, временные загрузки и RAM-файлы:
/bin/sh /net/hu-omap/mnt/umass*/nbt-aad.sh uninstall --purge --restart-hmi
```

Без этих флагов сохранён прежний режим архивного удаления, описанный выше. Windows-приложение по умолчанию использует **сохранение настроек**. Повторная установка использует оставленную конфигурацию.

Полная очистка необратима: после завершения транзакции удаления резервные копии стираются, автоматический откат на этом этапе уже невозможен. При сбое очистки скрипт сообщает об ошибке; повторите `uninstall --purge`. Копии и незавершённые загрузки очищаются и при уже отсутствующей программе. Журнал этой операции остаётся в терминале/на ПК, новый журнал на ГУ или USB не создаётся.

Очищаются только известные пути NBT-AAD: `/opt/aa`, папка плагина `NbtAad`, `/var/opt/aa`, обе папки копий, каталоги `/var/opt/nbt-aad-pc-<32 hex>`, перечисленные в скрипте RAM-журналы и файлы состояния. Файлы на флешке/ПК, общие кэши HMI и системные журналы, SSH, CarPlay, кодирование и Bluetooth-сопряжения сохраняются. Нестандартные пути, указанные вручную, требуют отдельной проверки. Это не обещание уничтожить все исторические следы в прошивке. До перезагрузки загруженный плагин HMI может создать RAM-файлы заново.

Номера установленных сборок и точное совпадение с локальным релизом по SHA-256 показывает **Состояние** в Windows-приложении, включая ручную установку. USB-команда `status` по-прежнему показывает пути и процессы; она не запускает демон ради проверки версии.

## Дополнительные параметры

```sh
# Посмотреть наличие компонентов и процессы; без изменений:
/bin/sh /net/hu-omap/mnt/umass*/nbt-aad.sh status

# Явно выбрать флешку при неоднозначности (имя здесь только пример):
/bin/sh /net/hu-omap/mnt/umass00100t12/nbt-aad.sh install --usb /mnt/umass00100t12

# После установки сразу перезапустить интерфейс:
/bin/sh /net/hu-omap/mnt/umass*/nbt-aad.sh install --restart-hmi
```

`--restart-hmi` вызывает `OnOffDSICommander appreset` только после успешного завершения файловой операции, сохранения журнала, освобождения блокировки установщика и финального `sync`, если эта утилита установлена. При ошибке установки или в `--dry-run` перезапуск не запрашивается. Перезагрузка ГУ может закрыть SSH. Дополнительная ручная перезагрузка после успешного `appreset` в этой инструкции не требуется.

Автоматический переход передаёт исходный текст скрипта в `/bin/sh -s` на `hu-omap`, сохраняя все аргументы. Подмена строк команд через `eval` не используется. Если после одного перехода текущий узел по-прежнему отличается от `hu-omap`, скрипт останавливается. Имена флешек и `--usb` после перехода относятся к `/mnt` узла `hu-omap`.

Скрипт не меняет SSH, активацию CarPlay, FSC или кодирование автомобиля. Он не возвращает файловую систему в read-only автоматически: завершение с полной перезагрузкой соответствует официальной процедуре. Временный SSH после перезагрузки может закрыться; установленному Android Auto постоянный SSH не требуется.

## Резервные копии, ошибки и журналы

Каждая операция получает уникальный идентификатор вида `20261104-140000-12345-install`:

```text
/opt/nbt-aad-usb-tools-backups/<ID>/
├── action
├── operation.log
├── COMMITTED             # появляется после завершения файловой операции
├── aa/                   # прежний /opt/aa, если существовал
├── plugin/               # прежний плагин, если существовал
└── var-backup-path       # путь к резервным настройкам при удалении

/var/opt/nbt-aad-usb-tools-backups/<ID>/aa/
```

Резервные настройки `/var` остаются на своём разделе: перемещение не требует копирования с последующим удалением между разными файловыми системами.

При обычной ошибке или перехваченном сигнале во время замены скрипт пытается восстановить прежние каталоги. Демон после отката остаётся остановленным. Результат отката выводится в терминал и журнал. Если восстановлению мешает ошибка файловой системы, скрипт сообщает `ROLLBACK INCOMPLETE`, сохраняет резервные данные и не пытается принудительно удалять занятые каталоги.

Это не защита от потери питания, зависания ядра или SIGKILL. При таком прерывании нужно проверить содержимое резервной папки до повторной операции. [Ручное восстановление](docs/RECOVERY.md).

Копия журнала по возможности сохраняется в корне найденной флешки как `nbt-aad-tools-<ID>.log`. При недоступной флешке основной журнал остаётся рядом с резервной копией. Кроме явно выбранного `--purge`, старые резервные папки автоматически не удаляются: при большом количестве обновлений нужно следить за свободным местом.

Одновременный запуск блокируется каталогом `/var/opt/nbt-aad-usb-tools.lock`. Он удаляется при обычном завершении после проверки PID владельца. Если процесс был убит или оборвалась сессия, сначала проверить журнал, PID в файле `pid` и резервные каталоги. Нельзя рассчитывать, что перезагрузка обязательно очистит `/var/opt`: размещение зависит от конфигурации ГУ. Удалять блокировку при работающем установщике нельзя.

Коды завершения: `0` — успех / успешная проверка; `1` или `2` — ошибка / неоднозначность; `3` — файлы уже установлены или удалены, но автоматический перезапуск HMI не выполнился.

## Проверка и публикация

```sh
sh -n nbt-aad.sh
python3 -m unittest discover -s tests -v
```

Проверяются также автоматический переход между узлами, сохранение аргументов, защита от зацикливания и порядок действий перед перезапуском HMI.

Тесты перенаправляют пути временной копии скрипта в отдельное дерево каталогов. Команды `cp`, `mv`, `dd`, `diff`, `wc` и оболочка выполняются реально; QNX-специфичные команды подменяются. Проверяются также ошибки копирования, отказы переименования и сигналы в середине операции. Реальные пути `/opt`, `/var/opt` и `/fs/sda0` компьютера не используются.

В репозиторий входят скрипт, тесты и документация. Файлы релизов NBT-AAD, личные журналы, фотографии, сетевые записи и данные машины в него не включаются. 

## Источники и лицензия

Основа процедуры — официальные [install.md](https://github.com/Sq00ky/Supra-iDrive6-Android-Auto/blob/main/install.md) и [updating.md](https://github.com/Sq00ky/Supra-iDrive6-Android-Auto/blob/main/updating.md), проверенные 4 ноября 2026 года. Формат `pidin`, параметры `dd`/`diff` и встроенные команды ksh сверены с документацией [QNX 6.5](https://www.qnx.com/developers/docs/6.5.0SP1.update/com.qnx.doc.neutrino_utilities/topic/about.html).

Этот независимый установщик распространяется по MIT. Сам NBT-AAD принадлежит его авторам и распространяется по **PolyForm Noncommercial 1.0.0**. Его бинарные файлы, библиотеки и ресурсы здесь не распространяются. Лицензия MIT на установщик не меняет условия использования NBT-AAD. В публикациях нужно ссылаться на исходный проект и его авторов; это не официальный установщик Sq00ky.

С версии 0.4.1 полная очистка сохраняет возможность отката отдельно применённых правил `pf_aa`: при найденной копии `pf.bak` и оставшихся правилах TCP 5277 она останавливается перед изменением файлов. После восстановления правил утилитой полную очистку можно повторить. См. [PF-AA.md](docs/PF-AA.md).
